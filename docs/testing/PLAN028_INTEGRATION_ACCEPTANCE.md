## 2. 一次性梳理交接契约，避免逐层补洞

检查当前实际代码，不照搬旧名称判断成功：

1. **就绪**：TLS认证成功、配置/MTU安装读回、双方原生数据面可用是不同阶段。客户端本地READY不能证明服务端Commit。优先复用现有认证收件/控制证据；不能仅为了测速双向而依赖反向业务，必须检验纯上行、纯下行、稀疏/暂无业务。确有缺口时做最小冷路径修复，不增加稳态逐包协议。
2. **交接**：A继续服务，B失败只清B；B真实可用后才发布唯一新TUN入口。全部新业务只给B，A只排完已接纳/在途工作；Go延迟Stop和Rust worker实际存活必须一致。Game热替换一lane不能清空健康兄弟及会话去重/FEC。
3. **边界**：Go/Rust早到DATA容量、字节上限、分批处理预算分别对齐。64包暂存与32包单轮处理可以并存，不能混为32包总容量；64/65边界用真实owner验证。正常容量溢出不应销毁已认证候选，畸形/跨代数据不能因此放行。
4. **路径**：真实物理NIC、源IPv4或已知effective MTU变化均通知现有控制器，200ms静默/最长500ms合并后读回；同NIC/IP的MTU变化不能忽略。网关噪声、TUN自身事件不盲目重连。用户外层默认1460不改，完整新代认证后按Rust预算安装；不宣称实现原socket热收窄或主动公网PMTU探测。
5. **生命周期**：Health不延长payload idle；丢保活不是无业务。睡眠后真实业务可重建；用户Stop、过期候选、旧回调不得复活或伤及新代/其他client。高损允许候选重试，不能为了轮换次数强拆仍可用A。

## 3. 先建立计算账本，再选择压力和容差

每场只记录关键输入/公式/预测与实测差异，复用脚本，不另造建模平台。

- 明确速率是**每方向内层业务**还是外层整条线路，双向分别统计。业务包速率近似 `P=B*10^6/(8*E[L])`；TCP应用写入长度不是线上IP包长，实际PPS必须读回。
- 外层PPS约为业务PPS乘实际分片倍数、实际FEC符号放大和lane副本数，再加重传/控制；字节放大另算头部、补齐和短块。FEC读取实际 `k,r`，不能把固定档名称当每块都满。Game重复记录和FEC恢复均不重复计业务。
- `N_flight≈P_record*RTT`，RTT含双向传播和处理。例：200Mbps、平均1200B约20833业务包/s，250ms单向至少约10417个业务包在途；尚未计FEC/lane。20Mbps全64B约39063包/s，比前例更吃逐包成本。缓存按其真实职责算，不把完整BDP强加给仅抽样的表演式重传缓存。
- 队列时间约 `Q/P` 或 `8*Q_bytes/B`；槽、字节、寿命三界和内核skb开销分别核。扩大缓冲须同时检查排队时延、p99、恢复排空和RSS，不能只看drop下降。
- 独立同分布擦除、及时收到有效符号的系统性MDS块：源包残余丢失参考 `p*Pr[Binomial(k+r-1,p)>=r]`。Game同一符号L份独立且均及时发出时可用 `p_eff=p^L`，再代入共享FEC模型；不是把共享FEC当L套独立译码。实际副本没发全、迟到、混合k、突发/相关丢包、缓存退役、分片都会改变结果，必须按实测修正。不能用IID理论给共同黑洞规定零损。
- 机会式重复带宽分别报首次F（再分业务源与FEC修复符号）、重复R、控制C、总外层字节；遵循现行预算，不混 `R/F` 与 `R/total`。只看到非零不是上下限达标；测量层次不全就明确未测，不重写已定型算法凑比例。
- CPU至少报两端进程CPU-s、各热线程/必要抽样热点、每实际交付GiB或百万包CPU成本；Go进程含Rust库，不能按进程名归因。内存分用户RSS/峰值、内核队列和退休owner数量，不能因一次预热增长判泄漏。

模型是解释和预警，不是用来强迫实验达标。容差由足够样本量、相关性、RTT/截止时间和宿主波动决定。改变门槛须说明旧门为何不合理、保留原结果和新旧口径；不得放宽硬门或把无依据的秒级停顿算合理FEC残损。

## 4. 先让故障可定位，再改代码

沿真实链路留同一系统CLOCK_MONOTONIC时间轴和client/port/generation归属；跨机器单调时钟不能直接相减，未校时只做各端局部时序或应用RTT：

`业务实际发送 → TUN接纳/队列 → FEC源与修复计划 → 内核实际接受发送/errno → 对端原始收包 → tuple/校验 → AEAD/重放 → FEC输出 → TUN成功写入 → 业务首次收到`。

- 明确每个计数是计划、尝试、内核接受还是唯一交付；`raw_batches`旧字段实际为交付数，不能据此断言内核无包。程序recv计数也不是网卡入站证据；需要时补本场owned接口/qdisc计数、socket丢包/队列、线程CPU/进度，区分包未到与worker没读。
- 复用既有原子计数，外部500ms观察+应用10ms桶足以定位秒级停顿；更短问题再局部提高采样。默认不在热循环打印、不持久大pcap；独立观察仍有开销，记录诊断ON/OFF，不把开日志后不复现算修好。
- 一条缺陷在现有evidence中保留：触发条件、最早异常环节、候选因果链、准确SOURCE/产物/夹具、下一项能区分原因的实验、修复与未覆盖范围。不得把上行EAGAIN与下行无交付仅凭症状相似合并为一个根因。
- 对条件修复（例如连续EAGAIN才调socket）：必须观察触发、实际effective读回及随后发送/交付恢复。未触发的PASS只能保护正常路径。可用有界的真实socket压力/定向故障复现验证机制，模拟单测不冒充公网性能。
- 同一个假说先最小复现和候选对照，噪声需要时补一次反序/定向诊断；仍不能区分就换观测或计算，不连续刷seed等偶然绿灯。不能复现仍记OPEN/NOT_REPRODUCED；独立工作继续，不能把无因果的好样本宣布根因关闭。

## 5. 分层推进，广覆盖但不做笛卡尔积

### L0：分钟内完成交接边界回归

使用现有真实Go/Rust owner及确定性事件测试：SYN/TLS DATA/末ACK损失；服务端Commit延迟/拒绝；Go/Rust早到32/64/65包；旧代在途尾包+新路由+晚到Stop；Game整组与单lane区分；共享队列从部分积压恢复；同NIC/IP MTU下降；取消/超时/重试竞态。边界正反例和真实调用均要执行，零测试/编译成功不是通过。再选代表冷路径做小型真实网络回归，不让一个新单测迫使全矩阵重跑。

### L1：接线与功能组合短测，通常120–180s/场

七模式：Normal Off/固定最高/Auto、Game2 Off/最高、Game4 Off/最高。先容量内，Normal每方向5–10Mbps，Game逻辑3Mbps；低损基线0/1/5%按风险配对覆盖。每模式至少实际完成2次可核验交接；高损另列重试结果，不要求每次候选成功或人为凑成功次数。

| 覆盖轴 | 最小真实证据 |
|---|---|
| 单端口/身份/地址 | 同账号两设备+另一账号；Game多lane仍一个对外端口；自动/手动IP、冲突、续租、server重启重配；7天纯租约用可控时钟，不等7天 |
| 独立配置 | 不同cipher/FEC/outer MTU1460与1280同服共存；requested/effective/OS读回一致；变更一个不影响兄弟；错误参数有明确结果 |
| 业务 | 真UDP/TCP各自和混跑；双向/纯上行/纯下行/稀疏；TCP单流与少量并行流；TCP持续下载旁穿插小UDP/探针，无新增优先级功能要求 |
| 包型/MTU | 小包64/256、普通1024、派生内层MTU边界；MTU−1/MTU/MTU+1；DF0兼容分片、DF1/本地EMSGSIZE或现行ICMP行为；一次代表大UDP和大TCP写入，不强求30%时跨MTU大包零损 |
| 生命周期 | A→A+B→B、候选失败留A、Game坏一lane兄弟继续；idle/保活丢失/唤醒；无业务轮换；Stop与恢复竞态，精确资源回收 |
| 路径 | 真实OS网卡/源IP变化、同NIC有效MTU收窄、先断后连与重叠；单向/双向黑洞后撤损恢复；休眠切网不自醒、用户Stop不复活 |
| 外观与入口 | 有限握手/首包/轮换包头摘要，标准TLS无私有前导；GUI/CLI配置实际生效；既有DNS/分流/IPv6/portable受影响冒烟，不抢029/030新增功能 |

Linux x86和原生ARM64按完整任务交替，Windows真实Npcap/Wintun→Linux补独有驱动/通知/Stop路径；共同算法不在每平台穷举，平台独有交接不能靠另一平台PASS代替。继承有效同源证据；跨源复用须列未变组件、依赖和风险，受改动的交接不能借旧PASS。

### L2：容量校准、渐进压力和弱网恢复

1. **先容量标定**：0损伤，先短代表负载，再上阶。Normal内层每方向10→50→100→200Mbps；Game逻辑3→5→10→20Mbps，Game4最高FEC本轮上限20Mbps。已有当前后端容量证据可跳过已知安全台阶；确认瓶颈即止更重同族，不为了数字撞VM。历史500Mbps/300ms目标是模型参考，不是本轮强制验收。
2. **区分吞吐与PPS压力**：大流量以近自动内层MTU大包为主，另做中小混包及小包高PPS代表。不要默认500Mbps全64B为日常业务，也不能只有大包吞吐而遗漏小包延迟。
3. **配对覆盖网络**：持续独立损伤0/1/5/15/30%、单程0/50/150/250ms、上下行不对称；不跑全组合。低损选高带宽/高BDP，30%选容量内中等速率；至少覆盖最高损伤+最高时延的一条代表。FEC Off按实际线路和廉价表演式重复解释缺失，不能套最高FEC恢复门。
4. **突发/共同损伤**：在稳态随机损伤外加短突发和单/双向黑洞；Game必须区分各lane独立丢失与共同底层故障，测真实错开发送兑现率，不用p^L为相关黑洞担保。Auto正常/激进、上下行独立升降、网络切换后重启估计代表性覆盖；升档期不硬卡业务损失，降档沿现行合格样本约120s一级。
5. **恢复是独立阶段**：选代表压力场景按“预热→稳定→短时约1.1–1.3倍已测可持续负载→恢复原负载继续业务”执行；不是每条功能/网络场景都额外制造过载，也不在已耗尽宿主上继续加码；过载可20–30s，恢复至少60s或按现行dead/退避预算延长。不能停发后的排空冒充有业务恢复。检查p99/最大空洞、goodput、队列年龄和RSS是否回落。

容量判断同时看发生器实际发送/滞后、宿主每核/softirq/steal/CPU PSI或可得等效指标、产品每线程CPU/等待、接口/socket丢包和队列。若发生器长期明显打不满（如偏差>5%且持续多个采样窗，需区分内层TCP自身拥塞）并伴宿主饱和，标CAPACITY_LIMITED、停止同族加码、计算未跑上限；仍保留真实缺失。**总CPU没满但一个产品worker/锁满，仍是产品容量问题**。0.6/0.85/近1.0倍实测容量可作为稳定/临界台阶，M0按PPS/宿主选择，不固定PSI一个数作万能门槛。

### L3：冻结源码后的最终综合质检

L0/L1必要范围齐，已知阻断在L2找到有效处置后，再冻结同一候选SOURCE。默认两条独立30分钟场景：①健康/低损多客户端，反复轮换+UDP/TCP大小包；②最有风险但容量内的异构弱网，含Auto/最高FEC/Game、过载回落、一次路径或黑洞恢复。历史相同矩阵不机械三份重跑；仅当存在未覆盖的不同失效机制才加第三条。新严重失败回到定向短测，不每修一点重跑整套长测。

所有模式/配置/OS独有入口用L1/L2覆盖表汇总，不要求一场塞入全部模式。长测关注累计泄漏、每轮资源回收、兄弟客户端连续性、p99及首到空洞。物理机/Android未跑单列，不伪装为Actions已验；不擅自部署用户机器。

## 6. 验收口径与停止规则

| 级别 | 判断 |
|---|---|
| 硬失败 | 非标准私有建链前导、串用户/配置/地址、payload损坏/重复交付、错误generation/原密文、未就绪撤A、Stop复活/失控资源、MTU契约失效；容量受限不豁免这些 |
| 业务阻断 | 容量内、实际持续发送且链路可用时出现无法解释的连续秒级停顿/跨流HOL；不得用已交付包p99或平均吞吐覆盖。750ms可作定位触发线，不是所有黑洞/重连/250ms单程条件的一刀切SLA |
| 性能判定 | 对照理论、同源健康基线、发生器能力和宿主余量；分别报goodput、业务残损、交付p50/p95/p99、未交付数、最长活跃发送无收件、CPU/内存/外层放大，不追随机小数点 |
| 可解释降级 | 超容量阶段有界丢包、超FEC恢复能力、共同黑洞、高损候选失败/退避可接受；必须计入结果，恢复后应回到已测可持续水平，不允许卡死或无限积压 |
| 证据不足 | NOT_RUN/NOT_REPRODUCED/NOT_TRIGGERED/CAPACITY_LIMITED均不是PASS；不因一次好样本关闭之前可复现的同类严重问题，也不因缺因果证据反复刷seed |

恢复预算按同源实测握手/数据接管分布、实际RTT、通知合并、发生的退避和现有dead策略计算。稳定业务与切网/真实黑洞窗口分开，但窗口必须由实际事件证据划定，不事后排除坏数据。FEC残损按实际块及相关性解释；短测百分位须有样本数量，成功包p99不能代表丢掉的包。

CPU对比只做同一VM、相同业务/包型/损伤、顺序旧新A/B，必要一次B/A；不同runner只能各报绝对容量，不能宣布百分比优化。优化无稳定收益或伤首到/p99则撤候选，保存负结果。缓冲自适应须证明触发、有效值、恢复及排队代价；不把没触发的普通PASS当机制有效。

## 7. Actions与最终交付

- 一Action一个网测场景；双端/多客户端是该场景必要进程，不另并跑竞争CPU的实验。独立场景独立Actions并行。同场分阶段和同VM顺序A/B允许。一次SOURCE按目标平台构建，复用manifest/hash产物；诊断参数和实际加速后端读回。
