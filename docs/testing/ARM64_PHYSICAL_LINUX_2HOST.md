# Linux ARM64: two physical hosts final acceptance (NOT_RUN)

Active scope: Linux AArch64 client and server only. Android, OpenWrt and Windows ARM64 are deferred. This checklist prepares **real physical device qualification**, not an assertion that it has happened.

## What is already proven and why this gate remains
- Original Go TLS/FakeTCP + pinned Rust data/AEAD/FEC2 + AF_PACKET raw/TUN have POSITIVE scoped virtual OS tests on `ubuntu-24.04-arm`.
- Normal/off and Fixed/Auto FEC, Game2/4 traffic, 60s 10 Mbps per direction, one Native/Scalar codec CPU ABBA, 1%/50ms and 5%/50ms bidirectional impairment, read-only FEC TX/RX Native counts, scalar-only no-ISA-L build, 8s idle, Stop and bounded client SIGKILL/restart have separate evidence in [ARM64 checkpoint](../evidence/arm64-linux-native-checkpoint-20261022.md).
- None of those substitutes for two physically distinct ARM64 Linux hosts with real NIC/driver/MTU, kernel and privilege settings, interruptions and physical transit. **Physical final acceptance = NOT_RUN** until there are two genuine host receipts at identical SOURCE.

## Safety/compatibility prerequisites, no implicit system-wide changes
1. Two independent physical native AArch64 Linux machines; record actual kernel release, distro/libc, NIC and MTU, machine/CPU model, quotas and clock source. Both must use identical native SOURCE and original Go credential material, and real network reachability. Do not use WSL, QEMU, a single machine with netns, emulator, or loopback as 'physical two hosts'.
2. Install only the **exact** SHA256-verified `arm64-public-bundle/` artifacts from the desired qualified Action, on both hosts: `wbd-v4-client`, `wbd-v4-server`, `libwbd_engine.so`, `SHA256SUMS`, `manifest.json`. Match architecture/ABI and original Go source. Linux glibc shared library is *not* interchangeable with arbitrary musl firmware; this is **not** the OpenWrt package test.
3. Run `bash tools/arm64_physical_readonly_preflight.sh /absolute/arm64-public-bundle` **independently on both hosts** and save stdout + host info. It only reads ELF/manifest, checksum and `/dev/net/tun`; it does not prove network reachability or required permissions. Never embed passwords or route key hex in shell command arguments.
4. Use an isolated test NIC/network or explicit administrator-approved route plan; do NOT replace a host's default route, flush global iptables, disable firewall, or alter external host settings as an automated 'fix'. FakeTCP may need a narrowly tuple-scoped TCP RST guard matching the *actual* NIC, source/destination IP and port, after explicit authority. Only call the traffic test PASS if the original Go TLS handshake, not a dummy socket, is accepted.
5. Create owner-only 0600 regular files for TLS private key, password, and route-key hex. Go CLI supports `--password-file` and `--route-key-hex-file` (same-fd `O_NOFOLLOW` validation). Avoid passing secrets via argv/logs. For server trust use a certificate/SNI that is actually acceptable to the original Go TLS runtime. Do not reuse publicly published fixture passwords or certificates.
6. Test client and server run with agreed `--raw-interface`, `--local-ip`, matching `--peer-ip`/ports, `--tun-name` and `--tun-ipv4`, `--server-name`, `--username`, `--password-file`, `--route-key-hex-file`, `--tunnel-id`, `--mode normal` first. The server additionally requires `--tls-cert` and `--tls-key`. Allow only privileged test processes to perform TUN, raw socket or scoped RST rules; don't automate changes to production NICs.
7. Capture both original Go READY logs, original Rust RX/TX counters, client/server OS TUN iface and actual independent application sender/receiver logs with monotonic clocks and SHA256; Stop each product with SIGTERM and confirm `STOP_DRAINED` and namespace/interface/route ownership cleanup. For Fixed/Auto assert **applied>0, pending=false** and authenticated original FEC source + repair; positive recovered count is required only when forcing genuine lost-source input. Never claim exact missing ciphertext PN from `tc` loss counters alone because protected PN/kind are not visible to a network injector.

## Independent real-network verification matrix (new Actions cannot fill this)
- **PHYS-N**: Normal/off two-way original TLS/data/Stop and fresh packets after missing/late packets. Functional PASS must precede rate statements.
- **PHYS-F/A**: Fixed and Auto modes, separately positive applied revision, authenticated source/repair, real TUN recovery vs M2 retransmit. Any burst, scatter, MTU or stop breach is FAIL.
- **PHYS-L1/L5**: kernel-measured 1%/50ms and 5%/50ms *physical* path impairment, independent scenario receipts per direction with actual app delivery, first useful application packet latency distribution, queue/pressure. ICMP RTT p99 is only a proxy, **not** first arrival p99.
- **PHYS-R**: real NIC interruptions and client kill/restart/new TLS credential, two hosts maintain Stop ownership; do not treat manual restart as automatic failover.
- **PHYS-A**: compare native ISA-L and independently built scalar-only on the **same** physical ARM64 host and clock/CPU quota with identical workload and exact SOURCE. Report actual Native/Scalar counts, CPU per useful byte, and app arrival latency; historical codec `15x` is not a product speedup.

Required receipt for each independent trial: `test_id`, `product_git_sha`, `harness_git_sha`, `go_source_sha`, `isa_l_sha` or `ABSENT`, `bundle_sha256`, `kernel`, `nic`, `mtu`, `cpu_quota`, `peer_machine_source_match`, `clock_type`, `mode_requested_applied`, `ready_and_stop`, `app_sent_received`, `fec_tx_native_scalar`, `fec_rx_native_scalar_recovered`, `loss_evidence`, `first_arrival_latency_p99_or_NOT_RUN`, `FAIL_BLOCKED_NOT_RUN`, and log/hash artifact references. Physical peer/source fields **may not** be inferred from a single runner.
