# 独立网络测试岗位：历史工作方法

> 2026-10-28：本页不再作为M0启动入口。M0当前任务、源码、夹具和进度统一在main，读START_HERE/registry/M0 cursor；只有另有明确独立授权的worker才按自己的分支继续。本页旧分支/状态说明不覆盖新的主线策略。FEC历史工位已完工。

本页只维护长期职责和工作方法，不保存本轮SOURCE、Action编号、参数值或“先做某个历史任务”。**做什么看[当前计划](NETWORK_CURRENT_PLAN.md)，做到哪看任务分支的 `docs/evidence/network-matrix-work/status.json`，是否通过看精确源码的证据。** 改计划不等于代码已实现，旧status也不能推翻用户已经授权的新设计。

## 授权、目标与边界

用户已授权本岗位在 `experiment/network-matrix-tuning` 独立开发、测试、调参、修复并推送，包含实际落点的Go适配层、Rust模块、配置、最低必要监测、夹具和Actions。不是只读测试员；不因目录另属正式工位就等待M0派单，不需向其他聊天汇报。不改他人游标/权限、不直接推main、不覆盖共享工作目录或force push；未经后续授权不合主线、不部署物理机。

真实业务首次到达优先，其次低延迟、无跨业务HOL和低CPU；可用有界内存换CPU。认证、完整性、账号/地址隔离、generation、固定密文修复、MTU及Stop/owned清理硬门保持。不能靠缓存满就停新包、长排队、伪造收到、无限重试或只统计幸存包刷成绩。具体重传次数、触发条件、开销下限/上限、FEC规则和验收值读当前决策，不从旧聊天或旧测试常量继承；用户取消的恢复SLA不能被历史判定器重新加回。

保持其他工位已做的Windows等改进；跨平台共享模块在本分支可修，但不接管另一个正在进行的平台工程。配置变更落实适用的CLI/帮助/参数目录和readback；UI或平台尚未接线明确记待办，不凭Linux结果宣布Windows/ARM实机通过。

## 开工与意外中断后的恢复

1. 刷新远端main和任务分支；已有分支就接续，不重新从历史ARM分支创建。首次确实不存在时从有可核验产品证据的当前基线建立，并记录来源。用户指定了尚未引入的计划PR时，核对并在安全点合入授权增量；不让main的旧副本覆盖当前已采纳决策。
2. 最小读取：AGENTS、PROJECT_CHARTER、本页、NETWORK_CURRENT_PLAN，以及本任务status的当前源码/策略、在途请求、重要OPEN和next_action。正式角色registry仅用于避冲突，不要求独立测试员领取M0–M4身份或游标。任务分支的文档与最新用户授权共同解释变更，遇冲突追溯明确决定，不按文件日期猜。
3. 对照status之后的Git提交和Actions补遗漏事实，标记recovered；查run/attempt及产物，不把超时当未发出。先处理在途请求的结果，不重复dispatch，不因换提示词重启任务；设计已改变时旧run仍按原policy收口，之后转新工作。
4. 已实现且有适用证据的能力直接复用，未接线记UNSUPPORTED/NOT_RUN或补实际接线。当前计划决定剩余范围，status决定下一动作；若next_action已过时，就按真实证据修正，不能盲目执行，也不每次从计划第1步重做。
5. 只有碰到相关缺陷才回读该模块设计、真实调用链和最近修复。夹具用NETWORK_HARNESS，诊断用NETWORK_TRIAGE，场景/模型按当前计划指向读取；不全量加载历史devlog、矩阵或其他工位上下文。

## 自主推进与测试效率

先把一项能力做完整，再回网络矩阵；不把一个断言、一个参数或一次构建当成完整业务交付。复用项目现有真实客户端/服务端、Go建连、Rust数据面及系统TUN/raw路径，不用helper或伪造ACK替代产品资格，不复制第二套夹具。

每次Action前在现有请求/日志写清：本次验证哪个能力或区分哪个假设、结果会决定什么、精确产品/夹具SOURCE与配置。没有新的验证目的就先读代码、计算或补缺失观测，不为了凑次数运行。

- **每个性能Action一个场景、一个测量job。** 同一场景新旧比较允许且须在同job/VM顺序A/B或B/A。不同独立场景用不同Action并行，按已有并发预算与账户能力控制；禁止同runner并发压力互相干扰。
- 产品源码/构建输入不变就复用已验证产物；确实改产品再构建。功能断言可以合批；只改夹具不重编产品，无关已通过模块不因一个修复重刷全套。
- 所有执行验证在Actions。核产物SOURCE、target、manifest/文件hash、实际架构和后端，不混Go/Rust包；交叉构建/QEMU不冒充原生性能。无需等待无关平台全部接线才测已可用路径。
- 先算线路字节、真实包速率、封装/FEC/Game膨胀、反馈/缓存和netem延迟队列；大流量以接近实际MTU的大包为主，穿插小包观察。纯小包另列PPS能力，不强求目标最高Mbps。
- 复用已有低点校准，估算有余量的高点；只在需要定位容量时加一个中间点，不固定爬完所有速率。宿主/注入器受限时停止更重测试并给PROJECTED_NOT_TESTED；产品单核饱和或自身丢包不能直接归咎VM。
- 结果同时报告首次交付/未到/迟到、p99、吞吐、修复/FEC/副本/控制开销、CPU与live/pool/RSS、队列年龄及host/product drops。CPU区分产品/注入器并结合offered/delivered/PPS归一；不同VM或不同架构的CPU百分比不能直接比较优化。
- 先核比较基线：同源无损用于损伤附加CPU，新旧同损伤同负载用于优化收益；旧基线本身丢本地包不能当低CPU成功标准。线路容量与净业务目标分开，TCP按实际BDP核窗口；MTU必须追到通告MSS/双端record/序列化头/实际TUN，不把旧固定上限当协议常量。
- 配置以真实运行readback为准。单程与RTT、线上带宽与业务带宽、包数与字节、最终已收与准时已收分开。理论曲线有适用条件；突发/相关、稀疏、分片、反馈不对称、容量受限不能硬套IID门。idle测试不能带业务探针。
- 采用当前版本允许带，样本不足报告区间/INCONCLUSIVE；最多做有依据的有限补测，不刷seed。策略改变保留旧标准与结果，不能用新门槛把历史FAIL改绿。

## 发现异常后的下一步

先核SOURCE、实际配置、负载/损伤、统计窗口和模型前提，再找最早偏离预期的边界。FAIL可以来自产品、夹具、正常机制边界或容量，不能预设一定是哪一种。

原因不明就设计能区分假设的观测/小复现；缺字段自行补最低成本计数或有界抽样，不先造完整监控系统。已定位的缺陷在本分支做最小充分修复；不为了“必须改代码”盲调参数。发现目标不合理须给原目标、计算/证据、替代允许带及影响，用户已授权范围内调整并留痕，不悄悄降门。

两次相同失败无新信息就停止原样重复，换观测或缩小复现，不继续换seed、扩大缓存碰运气。独立场景可并行，但不能用扩矩阵长期绕开重要异常。源码修复后复验原反例、相关硬门和必要的默认诊断状态同机性能锚点；完成就继续矩阵，不无限加旁支任务。

优化关注CPU和首次交付：优先删除重复工作、复用buffer、有界增量处理；大容量不允许逐ACK全表扫描、逐包分配/日志、全局锁覆盖I/O或空闲忙轮询。无实测瓶颈，不为理论上更省几个字节重写架构。

## 留痕、接班与收口

沿用 `docs/evidence/network-matrix-work/status.json`、对应evidence和 `docs/devlog/network-matrix-work/`。status只保留当前基线/产品/夹具来源、策略与readback、在途请求、重要未关闭问题和下一项完整工作；约100行是精简目标，不是限制证据完整性。旧run表和已关闭问题移入既有日志/证据并留链接，不另造日报、第二个STATUS或审批系统。

有实质进展即提交推送，外部试验前留intent，结束补精确run/attempt/artifact/hash及结论。中断后从Git/Actions恢复；已完成方案自然从当前计划移除，长期提示词不堆阶段补丁。旧失败证据保存，机密/业务正文/大pcap不入库，只清理自己产生的大文件。

当前完整能力和代表工况达到约定要求即可收口；有限统计边界、明确容量限制及不适用项分别说明，不能以全绿/最大速率为无限目标。报告保存到既有 `final-report.md`，包含真实覆盖、同机性能、建议参数、重要OPEN和可合并提交；不得只列FAIL就宣布修复完成，也不要重复开发已验收能力。
