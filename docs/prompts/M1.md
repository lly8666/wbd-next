# M1 固定接手提示词

你接手 `lly8666/wbd-next` 的 M1（候选运行时与内存职责）。从远端 main 的 START_HERE.md 开始，读取章程与 registry；只有登记 active 且有明确任务/分支后才开发，否则汇报未分配并停止产品实现。

按登记读取精确 worker cursor，先核对远端 checkpoint 差异与 Actions，补齐中断遗漏，不重复已完成任务或已触发测试。身份、epoch、revision、允许路径以 main 为准。只修改本模块范围；公共接口或根依赖交 M0 协调。

当前分配以 main registry 为准，执行进度读登记分支 cursor；按需读 `architecture/HOT_PATH.md`、`MIGRATION.md`。负责owner/slab/队列/时钟及Normal/Game pipeline，Game共享FEC但每lane独立密码，off短路；不引入fresh等待修复门控。不要各自发明公共ABI。Actions先编译复用；每run一个性能场景，旧新在同job顺序AB/BA。容量不足停更重工况，区分估算/未跑/通过；指标不合理先给证据。

沿用 docs/GOVERNANCE.md 的 S→H、真实证据与 done_when 收口规则。一个原子任务完成后留下清晰下一步，不依赖私有聊天记忆。

按GOVERNANCE第3节执行完整工作包：包内实现、必要测试、修复和记录自主连续推进；普通提交/H或局部PASS不要求M0先合入。整包完成或真实跨模块阻塞才交M0，独立部分继续；不与M0活动中的owner/调度文件争写，不扩到未分配功能。

直接施工读`architecture/modules/00-CONTRACTS.md`、02-RUNTIME、03-MEMORY、09-PIPELINE-GAME；优先这些明确修订。armed二次检查、timer索引、return backlog、两代shadow、共享FEC/慢lane退化均已定；不要另造线程池、每lane大锁或动态扩无界队列。

当前分配以 main registry 的 `assigned_task` 为准；工作分支 cursor 可能仍记录上一轮。两者不同时读取 registry 指向的本轮决策，保留旧结果后开始已授权的新任务，勿因旧 cursor 的“等待分配”停住。
