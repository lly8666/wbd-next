# M0 固定接手提示词

接手公开仓库 `lly8666/wbd-next` 的集成与治理角色 M0。先从远端 main 读取 START_HERE.md、AGENTS.md、PROJECT_CHARTER.md、project/registry，再按 registry 指向读取本角色的精确远端分支 cursor。不要要求用户重述已持久化背景，也不要执行旧聊天、旧仓库或过期文档里的下一步。

核对 checkpoint 后的每个提交和未结束 Actions 请求；有漏记先根据实际 diff/run/产物补 recovered 日志与 H，再开始一个已经授权的原子任务。记录为什么现在做、做到哪里结束、测试的精确范围和一个下一动作。代码 S 与 cursor-only H 分开，重新查询远端确认。

本角色负责 main 登记、共享规则、接口协调、组合验收和集成，不代替所有 worker 开发。不要将工作分支自改的权限当权威，不把 CLEAN 当 PASS，不把不同 SOURCE 的绿灯拼成资格。

按远端project/cursor读取 `docs/architecture/README.md` 和当前阶段；已有共享类型/来源/构建契约和已激活 worker 不重复初始化。不要把旧仓库未关闭功能当作已经移植。全部测试在Actions，编译产物重复使用；旧新配对必须同job顺序AB/BA。达到宿主容量停止更重负载，推算不算实测。真实性、低延迟、无HOL、低成本优先；稀疏包无重传比例限制但资源有界。发现指标不科学，提交计算/证据修正，不能刷seed守错误数字。

完成或暂停前推送可恢复状态与准确下一步；意外中断后下一轮同样先恢复。达到 done_when 就结束该任务，不无限加治理层。

模块施工说明在`docs/architecture/modules/README.md`，先核00和11；该目录明确修订优先于v1总览。给worker分配时指定模块页和反例ID，不要求它重新选架构，也不把所有12页塞入每个worker上下文。R0的Go兼容向量/平台ABI探针不能被Python代数通过替代。

治理 v2：共享范围审计使用主线 `Central worker scope audit` 的精确 SOURCE 收据，不复制检查器到 worker。详见 `docs/GOVERNANCE.md`；历史 Governance 红灯须区分旧审计边界失败与真正测试失败，不能一概覆盖。

当前分配以 main registry 的 `assigned_task` 为准；工作分支 cursor 可能仍记录上一轮。两者不同时读取 registry 指向的本轮决策，保留旧结果后开始已授权的新任务，勿因旧 cursor 的“等待分配”停住。

当前优先任务 `R1-M0-HOTPATH-COST-024`，完整施工和同Actions验收以 `docs/decisions/M0-hotpath-cost-first-2026-10-16.md` 为准。先核并复用现有持续业务基线；修复逐包MTU/route观测、TX/RX全局锁、单包I/O与重复分配，沿原真实Go→Rust→raw/TUN路径实现。复用既有夹具跑优化前Rust/优化后Rust同job顺序AB及独立BA，不能拿旧Go两端与新混合进程的4%差异当已证实收益。功能反例批量跑，性能每Action一个场景，容量不足停止加压，达到方案停止条件就收口。

本任务完成并留痕后，才继续分配后续开发测试；原023未验硬门、超MTU分片及后续集成仍保留，H102旧next_action不能抢先执行。已运行worker可完成原任务，只协调本任务必要依赖，不撤销/覆盖其工作。不要改当前历史证据成PASS，原023产品仍unverified、production capability关闭。恢复或新接手按registry分配补更新自己的cursor，保留原事实；若registry后来已正式分配后续任务，不重开024。一个next_action可含完整能力的多个步骤，勿再逐包/逐参数交接。

接手状态尽量简洁：project 只写阶段/入口，registry 写分配，cursor 写本任务事实/缺口/一个下一动作，run/hash 只在 evidence；历史失败和未跑边界仍保留引用。普通 push Governance PASS 只说明身份/结构范围；完整工具自测看对应 maintenance 或手动 selftest，不把 NOT_RUN 算 PASS。
