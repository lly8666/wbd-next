## 每次接手：默认上个 agent 中断，主动追上真实进度

**项目可能在上一个 agent 中断后又开发了很多，甚至有其他会话接续提交；项目记录、START_HERE、cursor、registry描述、聊天摘要都可能滞后。不得假定记录就是最新代码。** 每次新会话及关键写入前刷新远端 main、当前登记的工作分支、相关 PR、实际 HEAD 与提交图、在途/已结束 Actions、source/manifest/产物；按 [cursor](../../.governance/workstreams/M0/cursor.json) checkpoint 查增量和实际代码、相关新证据，先验收已完成的动作、查未登记的修复/失败，核实其他作者及冲突，补真实接续状态再推进。已发先收结果、已合先核实际 main；只有 WIP 继续原分支；未推本地内容未知。没有新证据不重复旧实验、不重新dispatch、不重开已否决方案。不能仅凭旧记录、聊天时间或缺少近期提交就认定另一 agent 已停止。遇竞争先核对，不覆盖、reset、force，不重复执行外部动作。

## 技术决策与开发纪律（硬约束）

**禁止任何防御性开发。禁止防御性开发。** 不为假想风险加多余校验、保护层、兼容分支、额外开关、兜底控制器、空轮询、审批、监控和抽象框架，不借谨慎无限缩小步子。该删除就删除，该改架构就改架构，该重构就重构；直奔产品最短依赖链，完整实现一项能力后验证。既有认证、完整性、合法报文、真实流控与资源生命周期、generation/隔离、MTU、owned Stop 以及具体已知正确性缺陷不是额外防御，不得借此口号删除或绕过。

**不要违心开发、不要为了讨好用户做不正确的事情。** 有事实冲突、性能退步或更优方案，直说依据、影响及替代；不是照抄用户假设，也不是为了反对而反对。不编造结果，不选择性报绿，不用多余复杂度证明努力。站位足够高：从完整产品的真实业务首到、弱网交付、延迟、CPU、系统 I/O、架构演进和跨平台共同机制反推任务，分清根因、现象、机制与成本；不钻牛角尖，不在已无价值的微优化上反复试，不为局部指标牺牲全链路。开放研究、因果诊断与方案选择读 [研究规则 v5.1](M0-RESEARCH-v5.1.md)。普通实现决策自主大胆推进；仅对会改变目标/权限/红线的真实问题请求用户决定。未经授权不委派子代理，不部署物理机器。

## 项目不变边界

保留成熟 Go TLS/OS/GUI 冷路径、原标准 TLS1.3 建链与服务器认证，TCP-like/TLS-like 稳态外层、既有加密及 FEC 契约，不改成另一种外层协议；不在 TLS 前增加私有前导，不把稳态说成标准 TLS。原 MTU 默认完整IPv4 1460B（不含L2），内层预算由Rust推导。Rust 长寿命稳态 owner，不逐包Go/Rust FFI、不等待凑批、不忙轮询、不跨业务HOL、不引入第二个反馈控制器；废弃 M2 不复活，原冻结密文外层机会修复最多一次。项目性能第一，允许必要有界内存，真实应用交付先于单项CPU指标。最新授权允许的模块重构与协议边界区分清楚。

## 治理、验证和交付

main 唯一任务登记/接班/集成入口；按 registry/决策登记的精确基线和唯一实验分支持续提交 WIP，首个实质施工push后开同一 Draft PR，按实际可验收增量与治理集成，不自建工位或另复制游标。每批次完整写齐实现、调用方、配置/GUI、夹具、装配和功能卡再冻结SOURCE。所有运行验证在 GitHub Actions；先查同SOURCE在途结果，按原intent规则发起；同机同job顺序 A/B 或既有 ABBA，固定场景、seed、配置、构件hash、实际架构及环境。功能与性能、物理资格分开，不以模拟、编译、测试替身或跨runner结果作性能PASS。真实应用bytes/hash/首到、TCP/UDP和Stop；按实际受影响范围测试、容量不足标明，不刷大矩阵。及时写短 devlog/evidence，保留历史失败及未测，不回写旧结论；实质提交S之后cursor-only H指向S。未验明确 unverified；整包未达done_when继续下一能力，不把局部通过当完成或等下一次派单。每次回答准确报告新增成果、证据、未解决和下一动作。
