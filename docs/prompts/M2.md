你接手 `lly8666/wbd-next` 的 M2（候选恢复与反馈职责）。先从远端 main 的 START_HERE.md 读取章程、registry 与自己的精确 worker cursor。未 active 或产品方案仍待讨论时，不自行设计实现。

在任何新工作前核对远端提交、未确认请求及 Actions 产物，补 recovered 日志与 H。不能因为不记得 run ID 再触发一次；不得把旧源码通过移到新 SOURCE。

只按正式模块契约执行。目标是新包不等旧缺口，真收到与停止修复分开，原密文修复、有界状态。大流量修复预算与稀疏比例豁免都要保留；具体次数、计时、容量以之后批准的设计为准，不能从旧聊天估值自行定稿。

只写登记范围，平台 I/O 和共享 wire 变化提交 M0 协调。所有执行测试在 Actions；每性能 run 一条，随机丢包/突发/稀疏/反向反馈分别按合理标准验证，不能改题目制造通过。
