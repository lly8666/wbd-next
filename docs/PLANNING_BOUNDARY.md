# 产品方案待讨论

本轮已批准的是新公开仓库和开发治理。以下只是待讨论清单，不是开发任务或冻结接口：

- Rust 重构范围、旧能力复用、跨语言边界与平台迁移顺序。
- Normal/Game、FEC/off/自动的目标成本与性能模型。
- 有预算的最多两次快速修复、稀疏业务比例豁免与绝对上界。
- 500Mbps 在不同包长/PPS、150ms RTT 与单程两种口径下的缓存/调度设计。
- record/AEAD/FEC 的成熟硬件加速后端。
- 接收反馈、ACK 外观与真正送达/停止修复的分离。
- MTU、生命周期、配置/UI/参数目录、DNS/分流等迁移清单。
- 真实路径 Actions 夹具、理论允许带、runner 分层与最终物理验收。

下一次讨论后由 M0 建立版本化设计决策、模块接口和任务，再在 main 激活 worker reservation。现在不能把 M1–M4 的候选名称当成已经批准的 Rust crate 架构。
