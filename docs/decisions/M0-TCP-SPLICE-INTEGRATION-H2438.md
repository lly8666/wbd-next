## Source-based integration assessment
The selected Linux TCP split is already native: Go cold control creates IP_TRANSPARENT listener, installs TUN-only TPROXY and policy route; Rust wbd-tcp-splice single epoll owner accepts, sets client-facing TCP_CONGESTION, uses two kernel pipes, splice with bounded per-turn quantum. No Go steady packet call or userspace stream payload copy. Native WBD receives complete IPv4 packets from its existing Shared-TUN, then per-generation TX encodes LINK/M1/FEC and RAW; RX authenticates and delivers original IP to TUN. The kernel-owned client-facing TCP socket is the real BBR endpoint; external WBD TCP-like carrier remains separate and is not kernel TCP. Existing record crypto and wire untouched. Sources:
- crates/wbd-engine/src/v4_linux_tcp_splice.rs: Pipe::pump, Flow::service, run, wbd_linux_tcp_splice_start/stop.
- r0/go_overlay/internal/v4productcli/tcp_splice_linux.go: startOwnedTCPSplice / Close, TUN PREROUTING rule, separate native owner.
- crates/wbd-engine/src/v4_embedded_go.rs: run_shared_tun_reader (batch8 scratch -> recycled Vec only on admission), native TX ingress (Shared packet -> original M1 arena copy), original TUN input, native FEC deadlines and generation/route ownership.
- crates/wbd-codec/src/record_crypto.rs: existing authenticated record/HP.

Strongest low-risk integration is control/lifecycle, not a replacement transport: keep the current Linux kernel TCP/BBR and existing native packet path; define actual socket pacing as explicit supported configuration only after testing combined default qdisc, multiple streams, Auto FEC and memory/CPU. No global fixed per-connection 540Mbps applied by default, no per-packet Go, no coupling of FEC feedback to a new congestion algorithm. Preserve independent Stop ownership and never switch accepted connections to NAT midstream.

Potential hot path optimization is general Shared-TUN memory ownership handoff, not splice itself: current kernel read -> scratch -> recycled Vec -> M1 slab. A future bounded buffer loan could remove one user-memory copy, but route is unknown until read, per-generation slab ownership/fair admission/feedback reserve/jumbo must remain intact; naive swapping 64KiB scratch into 1024 slots costs up to ~64MiB per lease. No proof this copy limits throughput: H2435 ARM 805–852Mbps outer zero full drops, H2437 all paced clean. Defer; no rewrite unless profile identifies material cost or new target requires it. Do not merge epoll and native TX/RX merely to reduce thread count; separate readiness and pacing avoid cross-flow HOL and missed FEC/health deadlines. Existing splice native same-VM capacity ~39Gbps is ample. TPROXY is not userspace TCP stack. Stream-level multiplexing or replacing IP records with socket payloads changes inner data semantics and requires client protocol changes; reject for this project. A different outer format is not needed for the approved goal; keep existing on-wire record format and interoperability, not a guarantee of identical packet timing. No claim about third-party traffic classification.
