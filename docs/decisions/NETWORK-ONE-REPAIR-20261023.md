# 外层一次修复：固定容量上限、按需使用、及时回收

状态：2026-10-23用户明确授权的下一版设计；**尚未实现/验证**。本决策覆盖旧外层“最多两次重传”、对应 p³ 模型及低损门槛，不覆盖FEC自身冗余数量、内层TCP、握手重试、keepalive/黑洞恢复。真实首次到达、无跨业务HOL、低CPU优先；原认证、完整性、固定密文、generation、MTU和Stop门保持。

实施者是现有 `experiment/network-matrix-tuning` 独立测试agent，沿用其status/devlog/evidence，不新建工位、不要求M0派单。先结清自己在途请求，保留旧结果；在安全点引入本决策，不覆盖已做的RTT/MTU/观测修复。读取时该分支HEAD为 `7aca769a`，status仍列 `39901422471` 配额结转A/B在途；这是读取时快照，不是最新Action结论。无需继续为第二次重传优化调度。

## 1. 用户澄清后的容量原则

**固定足够大的上限 + 实际按需占用 + 确认/修复后及时回收。不要再开发一套按实时PPS反复扩缩ring的控制器。** 数学模型用于离线定容量和测试解释，不放进逐包热路径。内存换CPU可以，但大上限不等于预分配全部payload、不等于允许长发送队列。

| 对象 | 本次决定 |
|---|---|
| shadow槽/密文字节 | 按目标极限及余量定固定逻辑上限；payload池按需增长、复用，不能每lane启动就实分配最大密文空间 |
| receipt历史/replay/成熟质量观测 | 上限覆盖同一PN速率与时域；bitmap/小元数据可适量预分配，较大状态按页使用。实际保留与shadow所有权分开 |
| endpoint内存 | 所有客户端、方向、lane共享同一总上限；初始沿用512MiB高吞吐预算，低内存设备可在启动时设低值并报告能力边界 |
| 修复速率 | 绝对天花板覆盖最大工况；运行时仍只花真实首发挣得的约10%字节额度，稀疏例外沿用有界绝对额度。不能给低速连接直接发满500M profile额度 |
| burst/发送队列 | 不按链路BDP堆排队；保留小burst、短queue-age、新包公平服务。大缓存只保存可修复副本，不制造积压 |
| PTO/保存期限 | 仍按真实认证RTT/抖动决定。固定最坏容量不意味着低RTT也用最长等待时间 |

固定小metadata数组可以比复杂分页更省CPU，不要求所有字节都按需；例如131,072×96B约12MiB/方向，只是布局预算。不得配套预分配131,072×2048B密文；多个lane/client也不能各自领取整机全部额度。冷配置、观测清楚即可，不新增按用户难以理解的几十个UI旋钮。

## 2. 每个原始record最多一次网络修复

- 有可信后到/receipt证据时快速修复；稀疏/尾包无证据时允许一次有界PTO修复。两者共享同一个机会，不能各发一次。正常无损包不主动复制。
- 原seq/PN/nonce/密文不变，控制/外观ACK不冒充真实receipt。不存在或已退役的shadow直接结束查找，不重建密文。
- 过程为 `Waiting -> RepairQueued -> RepairSending -> Retired`；真实receipt、过期、预算/内存压力也能让Waiting/Queued进入Retired。精确状态名复用现有结构，不要求另造框架。
- **修复已接受或可能已发送，即不再安排任何网络重试，也不等待这次修复的ACK来保留payload。** 明确未提交的EAGAIN/暂时背压可在原短deadline内重试本地提交；不重置期限，不把提交失败伪装成功。uncertain按已消耗唯一机会及额度保守处理。
- 缓存移交/释放引用要遵守I/O所有权：同步复制接口返回后可回收；异步/借用发送由completion或可靠取消后回收。不能为“马上释放”引入悬空引用。若保留引用会引入复杂共享计数，可复用现有有界TX staging复制一次，不为消除一份copy重写架构。
- `RepairedRetired`只表示已停止本地修复，**不表示对端收到**。FEC applied、auto质量、认证RTT、TCP外观等确需的最小元数据/receipt仍独立保留；不得把payload清理导致的未知当成已送达或线路丢包。
- 接收端本来就不等待缺口；无需增加“我不重传了”的协议报文。迟到的合法首次包在接收generation/去重窗口内仍交付，不能因发送端缓存退休就拒绝；重复包不再交业务。

## 3. 清理实现：O(1)定位、有界批量、少分配

agent复用当前ring/arena/timer，优先最小改动：

1. receipt按变化bitmap和完整PN定位，candidate同时校验slot generation；释放幂等。旧ACK、旧timer、重复completion不能误释放复用后的新slot。
2. 确认即释放；一次修复移交后撤销后续repair资格并释放shadow引用；到期/压力丢弃最旧repair-only记录。fresh资源独立，缓存不足只能减少可修复性，不能停读新业务。
3. 复用free-list、分块pool及已有有界timer；不逐包malloc/free、不每个ACK扫全表、不每毫秒扫65k槽，不为每包建立第二轮定时器。过期采用已有到期结构/发送次序游标并限定每轮工作量。
4. 空块先回到可复用pool；短低谷不立刻归还OS。连续低使用约30s后，低频批量释放超出暖池的完全空块即可；30s只是初值，不做硬实时回收门。严禁移动在途buffer。无需为此更换allocator或发明通用内存管理层。
5. 冷启动低负载不触及全部大块；高峰后live bytes应随ACK/一次修复/到期下降，pool reserved/RSS允许有界滞后。RSS可能因allocator保留而不立即下降；分别报告live/reserved/RSS，不能只凭RSS判泄漏，也不能让无界暖池掩盖泄漏。

**用户追加强调CPU成本**：ACK/完成/淘汰只处理实际命中的状态；收空块只遍历空块候选，不遍历所有payload。优先复用owner线程和现有批次，不添加后台逐slot扫描线程或逐包全局锁。到期回收起步每轮32项/约0.2ms工作预算，仍有工作再让出并调度下一批，不因大面积同时过期卡住收发；具体量子由测量调整。完全空闲时没有1ms轮询清理/空报告，睡到下个真实事件或到期时间。回收工作不能在同一轮被重复deadline立即重入造成忙循环。缩小RSS优先级低于CPU和新包时延，允许保留少量暖池，不能为了占用好看逐包归还OS。

## 4. 一次修复的参数预算

保留真实R、V、W和PTO：`W=clamp(R/32,2,20ms)`；`PTO=R+max(4V,2W,4ms)+10ms`。没有可信RTT时沿用保守bootstrap，不能读netem真值。

**用户后续明确最大按单程300ms、RTT约600ms设计**；容量预算也覆盖500Mbps与RTT600ms组合，但不强制重跑此前所有性能点。不能把300ms当RTT。RTT/抖动仍实测，超过范围报告受限，不通过截断RTT估计而提前重传。

一次机会的初始最大保留时间建议 `Tretain=min(1500ms,max(PTO+100ms,1.25*R+100ms))`。100ms是包含本地调度/反馈余量的工程初值，不是新增等待；正常ACK或修复提交会提前释放。新期限从原发时起，重复反馈/额度等待不续命。没有足够时间在hard deadline前合法发出一次修复就放弃并计原因，不把PTO硬压短制造误重传。接收去重/质量历史及测试drain必须容纳已发出的最后修复，不能全都照抄发送payload寿命。

V=5ms时，RTT400ms：PTO435ms/Tretain600ms；RTT600ms：PTO647.5ms/Tretain850ms。RTT600ms且V=50/100ms时，PTO810/1010ms、Tretain910/1110ms。固定1.5s最坏保留上限覆盖这些例子并留余量，不保证任意多秒排队仍可修复。设计占用估算仍为 `1.25*PPS*Tretain`；这是离线预算，不要求运行时动态resize。

| 主工况 | record速率口径 | 最坏保留槽估算 | 固定设计建议 |
|---|---:|---:|---|
| 500M/RTT400/off，80%线路且预留10%修复 | 32,468/s | 按600ms保留为24,351 | 正常占用小于固定天花板，不做动态扩缩 |
| 500M/RTT600/off，不预留控制/修复的首发上界 | 44,643/s | 正常850ms约47,434；按硬上限1.5s约83,706 | **固定131,072逻辑槽/方向上限**，覆盖最坏保留+25%余量；payload按需 |
| 50M/RTT600/max16:20，原容量模型 | 3,251/s | 正常850ms约3,455；1.5s约6,096 | 可复用同一高逻辑上限，实际只使用少量页/块 |

大包为主，纯小包500M不属验收目标。最坏1.5s保留加25%余量，83,706×2048B约163.5MiB payload预算；可用单方向192MiB、endpoint全部repair池合计384MiB作为初始硬上限，同时受总512MiB和fresh/RX/FEC保留预算约束，不叠加为每client额度。较小slab可节省内存，但无CPU证据不为此重写allocator。计算需计实际布局、页碎片、I/O持有和其他状态；打到字节/槽限制明确Abandoned，新包仍前进。

健康无损仍要保留约PPS×RTT的首发副本；所以不能承诺内存/CPU减半。主要收益是删除第二轮修复状态，并减少丢包/压力时的滞留、扫描和定时工作。

### 超时/回收分别定义，不能统一设为1.5秒

| 状态 | 初始设计 | 到期行为 |
|---|---|---|
| 未确认首发密文 | 上述实测Tretain，硬上限1.5s；确认或唯一修复移交后提前结束 | 撤销修复资格，安全释放；不假装收到 |
| 等repair额度/提交队列 | 沿用短20ms上界及原hard deadline，明确未提交可有界重调 | 放弃，不积攒一大串旧包；该20ms不是网络RTT等待 |
| I/O已借用buffer | 已有驱动completion/取消契约 | 绝不能因逻辑期限到了强制复用；有界在途/Stop取消，异常报告，不无限增加提交 |
| 收到包的receipt历史 | 固定容量支持约2s历史，2/10ms反馈节奏保留；不因重复报告续命 | 退役旧页，不把未覆盖页当丢包 |
| RX去重/晚到保护 | 初始3s接收相对时域，同时有PN容量界 | 合法首次晚到交付、重复拒绝；sender释放不是receiver拒收指令 |
| 质量成熟观测 | 保留现有约2s观测语义，补足PPS容量与反馈余量；仅小元数据 | 未知/删失单列，不因shadow释放冒充反馈确认 |
| FEC heavy/compact | 保留当前单独的相对到达期限/字节界，本批不统一改1.5s | systematic立即交付；heavy退役不禁止合法首次迟到，compact有界 |
| 空闲pool | 连续低使用约30s后低频批量处理完全空块，保留暖池 | 可延后归还OS；live引用及时释放，无空闲忙轮询 |
| 连接payload-idle/keepalive | 沿用用户配置及成熟黑洞恢复语义 | 不随repair清理期限关闭lane，控制包不伪装真实业务 |

容量示例：44,643首发PN/s加5%control余量、再加25%容量余量，receipt约2s历史可用512页×256位覆盖；3s去重可用262,144位约32KiB位图加必要页标签。实际control PN率必须核验；重传复用原PN不增加新PN，Game按各lane实测速率和endpoint共享预算计。大逻辑窗口不意味着同等payload分配。若现有成熟质量观测仍固定4k/8k，要补容量或压缩，不要为省密文把它直接删掉。

## 5. 用户授权放宽后的验收 v2（不要追零损）

等长、独立损伤、准确修复且反馈/缓存/预算足够时：`q_ideal=p²`，`repair/fresh≈p`。预算b=0.1时乐观下界 `q>=max(p²,p-(1-p)*b,0)`；10%/20%/30%分别为1%/12%/23%。只解释数学可达性，不要求真实相关损伤命中下界。混合包按包数与字节分别报告，不能把字节预算直接套包数结论。

| Normal/off IID线路损伤 | 一次修复理想残余 | 新的稳态UDP残余参考上限 | 原门槛（历史保留） |
|---|---:|---:|---:|
| 1% | 0.01% | **0.15%** | 0.10% |
| 2% | 0.04% | **0.25%** | 0.15% |
| 5% | 0.25% | **0.75%** | 0.30% |

新允许带按 `p²+0.10*p` 再向上取整到0.05个百分点，容许约额外10%的首发缺失未能救回；用于健康容量、足量、已结算、无分片的持续代表业务。它是用户允许简化后的工程目标，不是概率定律。当前60s/max_loss_pct=1的诊断门仍不能代替上述正式目标。不要修改旧结果变PASS；记录`policy=outer-single-repair-v2`和运行时`repair_attempt_limit=1`，分清新旧SOURCE/规则。

- 首次业务延迟、新包持续推进优先。off的2%/5%整体p99可能包含一个额外RTT；允许带按R/PTO/反馈/本地处理计算，不照搬FEC低尾延迟门。同时报告未损业务、修复业务、全业务、deadline内到达和最终缺失，不用丢更多包改善幸存者p99。
- burst/相关、非对称反馈严重丢失、极稀疏、超MTU多片、宿主/产品容量不足分别解释，不强套上述IID门。稀疏免比例但仍仅一次修复；高损优先新包、预算、CPU、队列年龄与恢复，不追p²。
- FEC maximum持续30%代表业务≤1%的既有目标不因本次改变而撤销；按真实k/r和到达trace解释。Game独立/共同损伤分开，FEC冗余不是外层重传次数。
- 旧两次版本可能残余更低，新版不要求残余与旧版相同；低损目标、低CPU、首次交付与有界内存一起评价。不要在新版丢更多包时只看CPU-s下降；并报offered/delivered口径。不规定必须提升某个百分比。
- 有限样本报告点估计与区间；统计边界可按预先约定补一轮，否则INCONCLUSIVE。独立损伤可用二项区间，相关损伤看时间块/trace；不刷seed、不围着置信区间无限跑。结束注入后留足Tretain+单程传播及有界调度观察，正常业务停止不立即截断修复。

## 6. agent的一次完整工作包

2. 统一Go/Rust真实构造、共享Normal/Fixed/Auto/Game数据路径、配置帮助/参数目录和readback。不新增可恢复两次的默认兼容开关；未接线平台明确NOT_RUN，不重写M0的Windows入口。bootstrap/keepalive逻辑不误改。
3. 同步`tools/cost_model.py`、`tools/network_harness/envelope.py`、判定器/请求及相关单测；这些工具和`network-matrix-20261022-model.json`目前仍有旧两次模型，**本docs提交没有伪装更新了工具或产品**。历史JSON保留版本，生成新的带policy/attempt字段模型；旧产物不能拿新门槛静默改结论。
4. 一个便宜功能批次覆盖：ACK释放、一次修复后无第二次、修复也丢不再修、ACK与提交竞态、uncertain/重复completion、slot复用/晚ACK/timer、预算/过期、黑洞下内存有界且新包继续、Stop和冷启动/高峰后回收。复用已有关联测试，不为每个断言单独编译。
5. 用同VM旧两次/新一次顺序A/B复验原Normal2%/单程200ms失败；一个性能Action一个场景。再复用同SOURCE做5%代表点和无损保护，1%可作补充；先有信息增益再加点。不重跑整套MTU九组合来代替恢复验证。功能通过后继续容量P2与原网络矩阵，不为“完美回收”长期停工。
6. 高上限低负载须证明实际live/reserved受控且不全量触碰payload；容量检查同时查receipt/replay/成熟历史和O(N)扫描。一次低→高→低压力场景即可观察暖池/回收，超过Actions机器容量停止加压并给估算；新旧性能一律同VM，不直接比较不同CPU百分比。
