## 2. 外层重传：一个公共实现，低成本维持外观

### 2.1 目标、上下界与真实计量

- 机会式重传维持TCP-like外观，不承诺修复业务；尽量选有真实ACK/SACK缺口线索、缓存仍在且代价低的疑似丢包。反馈并非确定丢失证明；不加逐包控制回报，不让FEC恢复/Game副本冒充R。
- 同一原PN/Seq/密文最多一次，不重新seal；成功或最终放弃后释放可选影子。缺缓存/反馈/额度直接跳过，不能阻塞新包。不要顺带改变接收端首到/去重语义或删除必要校验。
- F=实际首发成功的外层DATA字节，含parity及各lane实际副本；R=实际补发字节；C=ACK/Health/Quality等控制。双方各方向分别报，统一IP或现有wire口径；L2额外54B等须声明，不能一端IP另一端L2。驱动未知另列并保守占预算，不伪称actual sent。
- 持续 `R≤0.10F`，另报 `R/(F+R+C)`，忽略C上限约9.09%。保留平滑令牌、8MTU突发、稀疏绝对额度/进程总上限。短窗上界含开窗令牌，稳态长窗核斜率。Game按实际总F合并核算，不能把稀疏额度乘lane/客户端数。
- 希望有成本可承受的上下界，**不恢复狭窄硬比例门**。`R/F≈min(0.5p,0.09)`仅解释参考，Normal已达标曲线作行为基线。0%应接近零，有损不应因旧洞/计时错误长期无机会。量过小先算候选覆盖/限速/到期，再决定收益；不能补已ACK健康包凑下限。
- PTO若保留，是有界可疑候选兜底，单列ACK-gap/PTO/过期/拒绝计数。H814的810ms标称自适应PTO、1.2s缓存底线只证明接通，不是永久最佳参数。无损若主要靠PTO盲补需查原因，copied>0不是充分验收。

### 2.2 先测Normal，再统一复用

Normal为唯一优化基准，实现在现有共享recovery/owner内；Fixed、Auto、Game2/4只做lane/方向、原密文句柄、发送完成、时钟适配。共享候选选择/退休/预算/一次补发逻辑，各lane仍保留独立Seq/PN，不能跨不同密钥lane共享同一密文。

首轮配对只需三类：

1. Normal FEC-off，10Mbps/250ms/0%，R OFF→ON：测没有修复时仍付出的账本成本。
2. 同模式30%（有疑问再补5%），R OFF→ON：测候选、淘汰和实际发包增量/比例。
3. 容量内50或100Mbps、近有效MTU大包、0%或5%：看PPS/缓存增长，不先硬压200M。

每类一个配对Action，同源码/种子/时长/包型/预热/排空；噪声影响结论最多一次反序ON→OFF。优化前后同VM A/B仍保持相同重传开关；不要把“关闭功能”称为优化收益。A5豁免不取消这些当前产品比较。

### 2.3 静态疑点与处理优先级（未证实为热点）

**算清限制再改：**80ms每lane最多12.5补包/s；若每lane首发2500record/s且包长相近，`R/F≤0.5%`，同样负荷增加lane不会提升比例。这不能靠增缓存解决。独立均匀抽样保留率s时，理想无反馈/到期损耗下 `R/F≤s·p`；30%损失用1/16抽样最多约1.875%，想9%需至少约30%候选字节覆盖，实际可能更多。不能任意省缓存仍保证相同下限。

Normal定型后所有模式只做适配与预算/切换/原密文/真实发送/Stop回归；同类问题修共享处，Game不能长期保留第二套复制版。目录名M2不等于线上Receipt，不为改名重构全仓。

## 4. 每批先算再测：理论不是死门槛

直接在结果表写 **输入/假设→理论区间→实测→差额来源→下一动作**，不另建治理表单。先核实际实现和夹具，再用现有 `tools/fec_v2_model.py`、`cost_model.py` 等。指标不合理可提出依据修订，保留旧结果，不能为通过偷偷改题。

| 指标 | 算法与误区 |
|---|---|
| PPS/放大 | `pps=B/(8×平均业务包字节)`，分母和Mbps同口径；按实际分片、actual-k、parity长度、lane副本算F，不将FEC2一概当2倍 |
| flight/内存 | `在途record≈首发record/s×RTT`，`BDP=B×RTT/8`；200M/1200B约20,833pps，500ms业务BDP12.5MB，未含FEC/Game/头部，也不是可选重传必须缓存这么多。区分容量/活跃/RSS/allocator保留/驱动buffer |
| IID FEC | 真正MDS系统码等长k:r，源残余 `p·Pr[Binomial(k+r−1,p)≥r]`，按源包数加权actual-k/r；部分块、不等长、parity未发完、截止时间、分片另修正 |
| Game | 独立副本off参考`p^L`：30%时2lane=9%、4lane=0.81%；同符号副本全发且独立才可把`p_eff=p^L`带入FEC。共因/错峰按损伤时间线/相关性计算 |
| UDP | 单包OFF约p；m个必需独立片约`1−(1−p)^m`。不要求优于线路，但内部drop放大须解释。独立样本参考`3√(q(1−q)/N)`，零缺失95%上界约3/N；突发按块/时窗估计，不把每包当独立，2个百分点仅粗筛不是统一PASS带 |
| TCP | 核真实snd/rcv窗口、RTT、流数/限速；无损受窗口/RTT/路径容量约束，有损还受拥塞算法/残余损失。off高损不要求线速；不凭单个平方根公式认定慢速合理，必要补同工况直连/基准 |
| 延迟/HOL | 同机时钟RTT/p99和lossless配对，跨OS/WSL未校准不能报单向p99；探针成功/超时/迟到、发送桶与10ms交付桶一起看。零桶可因发生器暂停/网络全丢，不直接叫HOL |

30%随机损伤最高FEC稳态业务残余<1%仍为目标，先确认实际模型/时限支持且非容量污染；模型预测超标就说明并做有收益参数修订，不刷seed。共因突发/黑洞另验新业务不被卡住与恢复，不套IID门。

## 5. CPU归因、优化与停止

### 最小观测

- 双向注入/首到goodput/缺失/重复/损坏，p50/p95/p99及超时，F/R/C、源/parity/副本、实际损伤、模式/MTU/加速器读回。
- 同测量区间进程user/system CPU-s、热点线程、Go GC/alloc、RSS高水位、driver/TUN/socket drop、队列年龄/长度、host busy/PSI/steal/配额。稳态与建链/Stop分开统计。
- Rust DLL在Go EXE内，进程CPU已含二者，不能再加一次Rust线程CPU。用采样调用栈分Go/Rust/系统调用/驱动；WSL guest与host虚拟化CPU分层说明，不能双重相加。测不到写未知，不因语言推断归属。
- 正式测量关详细诊断，疑点才一次有界采样profile。用已有worker计数低频读取，禁止逐包日志/计时/全表扫描。必要短抓包只留外层头/长度/方向/间隔摘要/hash，清理自有大pcap和正文。

### 重传成本与优化收益

同源同机等量offered窗口，报 `ΔCPU=CPU_ON−CPU_OFF`、`ΔCPU/CPU_ON`（分母零则不定义）、RSS差、每百万首发record CPU-s，同时报每GiB**实际首到业务**CPU-s及goodput，避免“多丢包所以省CPU”。ON多出的发包/驱动成本在总增量内，不能全算候选算法；必要才做“缓存不发”的诊断，不把诊断变永久产品功能。

不预先承诺重传占比。可把持续>5%总CPU增量或p99显著恶化作为调查优先信号，**不是硬FAIL门**；真实额外网络IO、成本和外观收益需一起解释。正常零损账本也要测，不能只测有损发包。

1. 先核发生器足量、实际损伤/路径，再找忙循环、锁、copy、内部drop，不靠大buffer隐藏延迟。N线可独立查FEC重复计算、Game去重/重复AEAD、唤醒/syscall/分配；已有反证如四槽recvmmsg无收益不重赛。
2. 热点占f、局部加速s，总加速 `1/((1−f)+f/s)`；彻底删除最多省f CPU。预计仅1–2%总CPU且无正确性/延迟收益，通常不值得继续；真实bug不因此忽略。
3. 同VM新旧AB：相同业务/损伤/配置，真实首到/吞吐不退、p99/超时/Stop无退化，变化超采样/顺序噪声才称收益。跨CPU的CPU-s不直接相除，不能移除慢探针改善p99。
4. host busy持续约90%且有PSI/steal/注入不足/drop佐证，停更重同族；单产品线程/锁先满记产品串行瓶颈，不甩锅VM。用PPS/放大推未测上限区间，不能写实测PASS。
5. 一项优化一轮配对，噪声影响决策最多一次反序，无收益撤回/停止，推进下一有价值事项。不穷尽优化，不追重传率小数点，不无限补观测。
