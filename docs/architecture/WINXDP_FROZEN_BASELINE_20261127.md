## Frozen architecture and decisions

- Adopt as **experimental reference**: native XDP carrier integrated with Rust original single TX and RX workers; Go cold TLS/control. Batch-ready only, no new thread, spin polling, batch fill wait or Go per-packet FFI. Fixed directly writes frame into TX UMEM; Normal retains original arena/seal and frozen ciphertext lifetime independent of driver TX completion. RX borrows registered frames then releases/reposts; native DNS separate. Preserve original WBD TLS/record/ACK/SACK/PN/Seq/MTU/FEC and one opportunity repair semantics. Official XDP SDK/driver1.4.0; Native preferred where supported, Generic otherwise. Do not change GUI/protocol. Product outer IPv4 MTU default1460 excluding L2,1500 explicit maximum; fixture MTUs1160/1400/1460 not product defaults.
- Qualified lab candidate: build WBD_XDP_PRESSURE_LAB=1, WBD_XDP_LAB_POLICY=rx-single, WBD_XDP_SINGLE_RSS=1 in fixture; RX16384 *2048=32MiB, TX2048 *4096=8MiB, TX batch16, RX quantum32. Original all-queue A has16 *32MiB=512MiB RX backing in fixture. Scope port_count==1 and non-UDP outer carrier (inner UDP may traverse it), not Game multi-lane/DNS. XdpRssGet existing table; preserve hash/key/table length, set every entry to existing valid processor, verify readback; hold scoped interface handle, release restores map; every A/B validates original map >1. One logical Q0 verified in Generic WSL only; not per-app RSS policy; changes lower-edge interface mapping. Do NOT silently enable adapter-wide mapping in shipping build. Release defaults remain all-queue path. Official XDP1.4 disable flag unimplemented (offload.c hardcodes Enabled); same-queue XSK redirect constraint.
- Keep TX2048, RX16384 per single queue, quantum32. Prior RX4096 lossy tests successful at lower load; earlier clean350 peak4914, no default reduction. Fixed/Maximum FEC arena3072 when applicable to existing Windows owner; not RX UMEM. Preserve existing Wintun lab setting/current product values. No dynamic buffer growth/queue migration in single reference.
- Adopt BBR transparent Linux TCP proxy as preferred *lossy TCP benchmark/deployment option*, not forced default; existing --tcp-proxy-cc bbr --tcp-proxy-port 46180, actual accepted sockets cc=bbr, no explicit lab socket pacing cap. NAT separate baseline; Windows sender owns upload CC. UDP unaffected by proxy. Linux splice source unchanged.
- **Do not promote**: queue0-only without real RSS remap (12/32); inactive pending syscall skip (mixed TCP/small UDP); RX8192 vs16384 (mixed CPU); multi-queue shared backing/recycler (real memory gain but silent Fill credits stranded, unnecessary complexity if single RSS works); Wintun source loan f679ae5 (reverted by 5b848eb, mixed CPU including +23% upload and +14.5% large UDP); Game batch J (small-packet regression); isolated TX batch16 historical regression, not proof larger batch alone wins. Retain experimental alternatives/history, not shipping requirements. No new defensive framework or duplicate congestion controller.
