# 长期运行路径重构方案 v1

状态：`DESIGN_READY / IMPLEMENTATION_NOT_STARTED / PRODUCT_NOT_RUN`。本次授权是完成方案和验证计算、治理工具；没有部署，也没有宣称 Rust 产品已完成。2026-10-14 用户明确的同机顺序 A/B 要求覆盖旧版“每 run 禁止 multi-leg”约定。

## 结论

采用 **原 Go 控制层 + 同进程 Rust 数据引擎**。建连、借站 TLS、认证、地址分配、配置/GUI、系统安装和网络管理沿用原方案；长期逐包执行的编解码、FEC、独立 AEAD、外层恢复、队列/定时器、TUN/raw 收发迁入 Rust。先减少重复工作和调度成本，再谈换语言的收益。不会重新实现完整 TLS、完整 TCP 栈或另一套管理平台。

Normal 是一条 lane 的同一引擎。Game 在一个逻辑方向只做一次 LINK/FEC，多个 lane 各自加密和发包；收到任意 lane 的有效 shard 都进入共同恢复状态。各 lane 的序号、密钥、nonce、TCP 外观保持独立。固定 off 走短路径，不创建 FEC 编码状态。保留自动档的旧决策算法与未关闭项，不趁重构另造控制器。

外层恢复最多两次、只重发原密文；真实送达、停止重传、外观 ACK 是三个概念。新包不受修复缓存大小或缺口门控。大流量修复约束在新发外层数据的 10% 以内；稀疏业务免比例限制，但仍有绝对额度、寿命和次数边界。4096 不再是固定可靠窗口：缓存按 PPS×保留时间算，并设共享内存上限。
