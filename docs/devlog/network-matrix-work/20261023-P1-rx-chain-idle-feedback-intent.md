# 2026-10-23 P1: causal RX chain and feedback-idle fault

Previous exact one-repair source e430951c native ARM64 [39906119466](https://github.com/lly8666/wbd-next/actions/runs/39906119466) passes 75/75 recovery and nine MTU boundaries. Real same-VM AB [39907046412](https://github.com/lly8666/wbd-next/actions/runs/39907046412) B failed true bidirectional steady UDP 2.481%/2.532% against v2 0.25%; both sides had 682 candidates, ~510 copied repairs and ~170 quota retirement. This does **not** prove repairs were useful. Native product had no RX open, replay, LINK/TUN or feedback-drop chain counters.

Static code proof of a concrete independent product bug: `start_loop` TX worker polls local TUN readiness 10ms and only checks FEC deadline before deciding to skip `background_tun_once`. Authenticated RX feedback is staged inside that function, but its `RxFeedbackState::next_deadline()` was missing from the outer idle-wake gate. If the peer sends while this endpoint's local TUN remains idle (unidirectional, tail or sparse), verified receipts stay pending indefinitely despite incoming data. This can force PTO candidates and waste quota, but it is **not yet** a verified explanation for the duplex ~2.5% residual. Fix: check feedback due in the existing once-per-10ms owner turn, no busy poll/new worker/unbounded queue, leave FEC and new-traffic priority unchanged.

Observability: no packet payload/PN/addresses or per-packet logs. Original M3 opener returns bounded increment-only cause counters: tuple-visible, unique valid DATA, PN older than authenticated receive highwater by >32, successful LINK completion, successful TUN sink, pending, malformed/discarded, sink failure, exact duplicate/retired/invalid AEAD. The existing RX worker aggregates these into 13 relaxed atomics *per batch* and publishes one pre-Stop V4_PUBLIC_RX_CHAIN line, plus RXFeedbackState retained pages/drop. This distinguishes absence before unique open, missed TUN delivery and already delivered replay, but data_lagged32 is a lower-bound timing proxy, **not** mathematically confirmed useful repair. No new wire interpretation. Harness retains marker and reports authenticated numeric readback, not PASS.

Next build on Actions; no local tests, no performance re-dispatch until native pass. Then one precisely pinned B-only Normal 2% diagnostic scene to determine whether remaining losses are at raw admission, AEAD replay, LINK, TUN, or high feedback-drop/abandon.
