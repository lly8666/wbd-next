## Open source Brutal vs BBR: what is actually port-able

- [HyNetworks/tcp-brutal](https://github.com/HyNetworks/tcp-brutal) is an independently maintained **GPL-3.0 Linux kernel module** implementing Hysteria Brutal; its v2 uses per-destination route/rate control, **requires known bandwidth**, can impose congestion on neighbors. Not upstream Linux BBR, not a Windows provider, not a Rust FakeTCP data-plane module; no permissive license asserted. No GPL3 code copied into WBD by this experiment. [HyNetworks Hysteria](https://github.com/HyNetworks/hysteria) also implements QUIC Brutal with genuine QUIC peer delivery feedback, which **is not WBD's unauthenticated appearance ACK**.
- The native sender algorithm (inner TCP) can be separately OS-selected on Win2025 or per-owned Linux TCP socket; WBD only owns its GoTLS/FakeTCP outer encrypted packet presentation, not arbitrary user application TCP sockets. Implementing a product `TCP_CONGESTION=brutal` on Linux changes real owned TCP only, not WBD's outer or Windows inner sockets. Installing GPL3 kernel modules on the customer host is NOT an ordinary default setting and is excluded here.
- For outer WBD, the only safe candidate is a bounded, **work-conserving native M4 ready-only egress pacing and per-lease fair admission** based on actual M4 copied bytes and underlay service, with cold capacity cap, one-shot immutable shadow/repair R/F≤10%, no per-packet Go control, no failed/forged appearance ACK as authenticated bandwidth/loss. No continuous DATA PTO, no cross-business HOL and no spoofed positive ACK for cwnd.
- Two independent congestion loops are **not automatically beneficial**: outer cap can clamp all inner independent TCP senders, and "loss compensation" increases line loss/queues without replacing lost IP datagrams; evaluate interactions with true CPU/GiB, kernel drops, independent first delivery P99 and fairness, and exact Stop before any production candidate.
