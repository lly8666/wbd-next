# Matched CUBIC and Linux BBRv1-style experiment

User requests old kernel transparent splice vs Rust CUBIC at 400ms zero injected loss, then old kernel BBR vs Rust BBRv1-style at 400ms 0/1/5% loss. New independent controller shares existing delivery sample, TCP state machine, RACK/SACK, pacing owner. Public BBRv1 design: https://queue.acm.org/detail.cfm?id=3022184 and https://github.com/torvalds/linux/blob/master/net/ipv4/tcp_bbr.c . Four modes, 10-round rate max, 10s min RTT, 3-round plateau, gain cycle, ACK aggregation, transient packet conservation, ProbeRTT 200ms plus round. First candidate is not exact Linux port: no LT policer detector, TSO-specific budget, randomized initial cycle or kernel recovery/rate sampler identity. No BBRv3 changes. Cold middle CC selector only; default stays BBRv3. Use old exact splice artifact with Linux CC and Rust same-named CC, cap64 middle, ACK3 and SACK compression enabled, same native endpoint kernel CC per case, identical outer/MTU/FEC/repair. Real same ARM triple sequential four ABBA blocks; compare full architectures, not claim isolated controller equivalence. Native function, core and actual measurement required before promotion.
