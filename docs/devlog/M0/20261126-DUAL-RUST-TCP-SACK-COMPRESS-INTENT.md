# M0 Linux-inspired SACK compression diagnostic

User requests reuse Linux ACK/SACK/GRO mechanisms. Linux 6.14 tcp_comp_sack_delay_ns=1ms, tcp_comp_sack_nr=44, 5% RTT; tcp_input sends first three duplicate ACKs per unchanged cumulative ACK immediately. Independent Rust implementation, not kernel C code copied. Only paired middle TCP, new above-hole data accepted completely with SACK negotiated, unchanged cumulative ACK, no duplicate/DSACK/FIN/urgent ECN feedback/window closure; first three gap reports immediate, after that existing delayed ACK deadline capped at 1ms or 5% RTT, max 44 pending. Existing ACK serialization uses current scoreboard, clears pending on any ACK. No new timer source, DATA batching, outer/FEC/repair changes, no default promotion. Unit regression checks early gap reports, bound, newest range, immediate hole fill and duplicate. Same diagnostic binary with candidate switch on/off, both ACK3 and cap64 at zero loss, loss10 at 1/5% (same settings in each matched pair); ARM 400ms 0/1/5% ABBA. Count actual wire ACKs/deferred, throughput, resource, retransmission, SACK and path receipts. GRO and sender scoreboard changes deliberately separate, not claimed implemented.
