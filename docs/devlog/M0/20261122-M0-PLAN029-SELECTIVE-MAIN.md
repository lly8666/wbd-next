## TCP P99 and BBR experiment scope (next independent fresh-main branch)

- The Windows 160 sparse echo values are pipelined on **one persistent TCP connection**, every 80ms, and are not independent connections' time-to-first-delivery or proof of cross-flow HOL. Capture send timestamp, first byte, recv, absent replies, kernel retrans/RTO, SACK, cwnd and app traffic, not survivor p99 alone.
- Original Windows Wintun user TCP traffic is **owned by the client OS/app**, original Linux TUN user TCP by server OS/app. FakeTCP outer carrier is user-mode appearance packets, **NOT a kernel TCP socket**, so changing congestion provider for WBD's fake carrier has no effect on user inner TCP cwnd. Windows supports OS TCP BBR2 template and optional scoped supplemental port/subnet filters; Linux permits TCP_CONGESTION per owned socket or a scoped netns; only if actually supported and read back, never assume Windows/WSL/ARM same algorithm. For external applications on Wintun, WBD does not own users' sockets; per-process congestion selection requires OS policy or explicit proxy terminator, which changes TCP semantics and must be separately authorized/qualified.
- Proposed first A/B/A' in fresh branch: **NO product code/default change**, same real 3Runner Windows/ARM source+underlay, original FEC OFF, symmetric 200ms/loss 0/1/5%; compare kernel TCP baseline CUBIC/CTCP vs Windows BBR2 and Linux BBR where available, one endpoint at a time then both; verify get/set/readback on exact selected OS, socket tuple, congestion class, rollback on every exit. Measure 4×25s sender-vs-drain, ARM real received bytes, TCP_INFO/RTO/retrans, p50/p95/p99 and missing tiny flows, UDP/other flow fairness, CPU/GiB, original driver Stop. Don't declare either end's BBR improvement without true TCP stack/socket change readback and counterfactual. Priority follow-ups: RACK/TLP where supported, delayed ACK/receive window limitation, RTO/retrans backoff, TUN/driver loss amplification, ACK/SACK original handoff.
