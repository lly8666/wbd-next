## Simpler RX route: port ownership instead of custom eBPF
Four tuple matching originally demultiplexes a passive capture shared with ordinary TCP and distinguishes generations/lanes; it is not cryptographic authentication. With XDP consuming packets, reserve the actual local IPv4/TCP destination for the lifetime of the lane via one bound, non-listening Winsock socket, then use stock XDP_MATCH_IPV4_TCP_PORT_SET (the upstream inspector uses destination IPv4 and network-order port bitmap). A different remote tuple reaching this exclusively reserved destination cannot belong to an ordinary local TCP socket; existing product parser remains unchanged at this stage. No per-packet new check, no custom kernel code. This changes cold port resource ownership, not packet bytes. The fixture tests actual competing local bind, two distinct real WSL TCP SYN source ports redirected, and an adjacent ordinary TCP listener still delivered by Windows. Multi-queue, cross-interface ownership, reconnect/Game lifecycle and product TLS handoff still need actual verification. Do not infer complete replacement from this isolated probe.
