# M0 R2 reverse Health/Receipt authenticated replay gate (2026-10-14)

Task `R2-M0-REVERSE-REPLAY-001` | M0 owns engine-only integration and shared Actions, **no worker ref changes**.

**Reason.** The main R1 business receive path is now M3 `ReplayProtectedLaneRx` protected, native codec 23/23 and first packet 3/3 qualified at SOURCE `ad0ae13fcbccab96dbee3540e7fa73ca40639cfe`. However main's M0 `BoundReceiptIngress` still accepted reverse Health through raw `LaneRxCrypto::open_in_place`; thus authentic but retransmitted/duplicated control records could re-enter M2 `on_receipt`. This was a real missing cross-role integration boundary, even though M2 receipt itself is idempotent for received entries.

**Scope of change.** Only after the caller supplies already-authenticated/session-bound reverse direction key/suite and nonzero matching lane + epoch, M0 `BoundReceiptIngress` now owns an actual M3 `ReplayProtectedLaneRx` with bounded, explicit configured per-lane memory and window. The only acceptance path is `&mut self.accept_one`: AEAD+authenticated inner marker and kind, M3 PN uniqueness/retired floor, then WBC4 decode/receipt binding, then M2 state. Raw AEAD opener is no longer accepted in constructor; duplicate/retired returns a specific replay error without calling `on_receipt`. Invalid tag never moves PN high water. Valid-but-non-Health or authenticated malformed WBC4 still consumes one unique PN; this is conservative and correct, no application delivery. Exposes read-only `replay_info/stats/max_seen` for effective capped metadata; no extra untrusted PN shortcut. M1 shadow stays original frozen bytes; M4 accepted/uncertain/notsent treatment unchanged.

**Native test plan.** Keep original three M0 real M1/M2/M3/M4 tests, adjust reverse record PN fixtures so two different authentic records never reuse the same PN/key. Add three real native cases: (1) authenticated repeated negative and positive Health receive only once, corrupt tag cannot poison PN floor, shadow only releases on fresh authentic unique receipt; (2) valid retired PN after authenticated 257 jump fails closed, no shadow release, higher fresh PN may ACK; (3) all three actual ChaCha/AES128/AES256 suites use real AEAD reverse Health and reject copies/modified ciphertext with real M2 shadow+M1 arena. Six exact integration tests total on one Rust1.85.1 Linux x64 binary compiled once and hash-verified separately; affected shared R0/R1/G2 and cross ABI Actions must finish at same SOURCE.
