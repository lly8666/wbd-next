# 实际 App UDP → KSU Root → TUN /32 接线工作包（2026-11-16）

**目标：** 收敛在唯一 Android16/API36 x86_64 KSU 3.3.1 AVD，不再重复既有 KSU 授权/Raw Socket 版本矩阵。原 KSU 正例 `0a4967b...` 的 UDP 是 root 原生进程发送，尚未证明**普通 Android 应用自己生成的 UDP**可以进入 Root 的 TUN。

新增 `AppFlowActivity`（目标 SDK37，正常 UID、SELinux untrusted_app，声明 Android INTERNET，不使用 VpnService）启动获管理器授权的实际 KSU `su -c`，执行同 SOURCE Rust `appflow APP_UID NONCE`。Root 子进程仅在确认 AVD/UID0、策略规则优先级8200与表235未占用之后创建非持久 TUN，配置 MTU1400、owned 测试网段198.18.253.1/30，临时路由表235 中只有 `198.18.254.2/32`，临时 UID 精确匹配优先级8200规则为 `uidrange APP_UID-APP_UID to 198.18.254.2/32 lookup 235`。它发 READY；普通 App（没有 SO_MARK/Root）用 DatagramSocket 发送 `wbd-app-<nonce>` 到该地址端口49492；Root 必须实际从 TUN 读到原 token 的 UDP 包，验证 IP/port/payload。Root RAII 删除自身 rule、route、fd，CI 的系统 IPv4 rule 和所有 route 的**前后快照逐字相同**才能 PASS。

**隔离范围：** 这一条临时 UID+目标 /32 规则确实写在一次性 AVD 的**主网络命名空间**，但不更改系统 main/default 路由、不转发/NAT、无 iptables/nft/netd 文件修改；仅精确测试包及合成地址命中。只在 Android 模拟器且 KSU real su 域下执行，拒绝普通物理设备。异常 SIGKILL 可能残留 rule，CI 随一次性 AVD 销毁，因此不是生产级恢复方案。不要将其标为 Android 系统 netd/tethering/真实蜂窝出口 PASS。

Native 仅当前 SOURCE x86_64 一次构建，APK 一次编译；标准 KSU Manager UI 仅授权本 APK；清理后整体动作由单一 GitHub CI 校验。保留此前真实 KSU 功能正例和失败、不重复既有 root 生成流量场景。新增文件 `probe/src/appflow.rs`、`app/AppFlowActivity.java`、`ci/appflow-case.sh`，旧 AOSP 负例 workflow 改为手动触发以减少已知失败噪音。

当前：**代码已实现，需真实 KSU AVD 实测确认，不预置 PASS。**
