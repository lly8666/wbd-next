## Scope and code

Only two original Game files: `crates/wbd-engine/src/v4_game_lane.rs` and `crates/wbd-engine/src/v4_game_public_kernel.rs`. Existing original TLS exporter lane RX key+IV/HP and `ReplayProtectedLaneRx` are **moved, never cloned or reconstructed** from the unified `GameReceiveOwner` into each lane's one actual Linux M4 worker. `take_lane_for_worker` moves state exactly once, strictly matching admitted LaneKey, before workers start; duplicate handoff returns Unauthorized. Each worker decrypts/authenticates the *original* wire in-place and advances its own PN replay window without acquiring shared owner mutex, then `decode_game` checks the typed Game authenticated logical ID and real inner MTU. There are no extra threads, global sockets, queues or payload copies.

The shared `GameReceiveOwner` retains exactly ONE `GameRx` cross-lane logical first-delivery window and ONE `GameFecRx` decoder, shared bounded arena and *actual TUN-success-after-kernel-write* reservation/commit logic. New `prepare_opened_receive` and `prepare_opened_fec_batch` take only already authenticated ID+payload from the lane opener; they still check scope/generation/lane, stale/duplicate and pending concurrent TUN writes, **never precheck untrusted ID**. The original `prepare_receive` and `prepare_fec_batch` wrappers remain for explicit in-memory native test/adapter callers, but production calls only post-auth stage. `lane_count` is captured before moving replay states so pending capacity remains the exact original 2/4 lanes. Neither per-lane ciphertext seal/PN nor FEC source/parity/0-4-20-60ms copy times, outerDATA OFF policy, borrowed TUN write or bounded Stop cleanup change. One worker-only original replay state drops only after its worker joined. The per-packet borrowed payload stays in the existing 2048B RX stack packet until the shared owner has copied it to its pre-existing bounded reservation.
