## Scoped P0 implementation, no Game-only filter

- A **single** `RawIPv4Endpoint.ExcludeDetachedData(peerIP,peerPort)` with reusable classic Linux `SO_ATTACH_FILTER` in `r0/go_overlay/internal/faketcp/raw_detached_data_linux.go`; appends exact peer source IP/port, TCP flags and total-length/header-length gate to the original AF_PACKET local-port/IP kernel program. Excludes only data-bearing records from the detached tuple, allowing pure ACK and SYN/FIN/RST, including SYN with data; leaves other peers' SYN/handshake untouched. Go control **sendFD remains open**. Data is excluded at socket ingress (not after user-space parse/copy), with kernel filter installation fail-closed when original port filter is absent. Rust AEAD/PN/replay still authenticates/guards actual DATA.
- Normal client: after `native.ConnectAuthenticatedPeer` returned ready and client association is `ClientAssociationDetached`, arm the filter for the authenticated peer, otherwise stop native and report error. Applies without FEC-mode branching: `off`, `fixed`, `auto`; keep Auto M2 feedback readback unaffected.
- Normal server: `AcceptAuthenticatedPeer` completes async original TLS and Rust loop setup, validates Detached and immutable association flow/local scope, then arms filter **before** publish-ready. On failure, call `product.Close` before surfacing error. Server's readiness flag is atomic for the receiver goroutine to avoid the prior concurrent `*connected` access; only the outer caller writes the externally owned result pointer. The existing admission/Stop lifecycle needs real regression, and the current code does not promise in-process multi-session restart.
- Game2/4: reuse the exact same `ExcludeDetachedData` API already wired by W129, after their authenticated group M4 commit, with existing physical stagger, parity ownership and Stop unchanged.
- Low-frequency `go_data_full_copies` counters sampled once at shutdown in each Normal/Game client/server, not a per-packet perf logger. Values must be established by real load; socket backlog at transition may leave a bounded initial tail. A zero counter is not independently proof of kernel send rate or Rust delivery.
