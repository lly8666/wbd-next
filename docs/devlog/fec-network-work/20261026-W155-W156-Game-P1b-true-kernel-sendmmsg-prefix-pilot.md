## P1b bounded transactional design (native feature OFF by default)

Existing scoped Game M4 TX performed `ScopedRawIpv4Tx::send_one` from `GameAdapter::drain` per physical copy; the project already has genuine native `ScopedRawIpv4Tx::send_kernel_multimsg`, which invokes one Linux `sendmmsg` with 2-iovec scatter header+frozen record, max32 same tuple. The old `send_ready_batch` merely looped send_one and **is not the optimization**.

New **opt-in diagnostic** `WBD_GAME_TX_MMSG=1` only for a selected Game2/4 Actions bundle (no Normal/Auto). GameTx `DispatchOutcome::Deferred` means a due, PN-sealed record is copied to its original bounded frozen kernel slab but **not yet credited** as a physical sent copy. `GameTx::finish_deferred` maintains bounded debt through one synchronous kernel turn, accepts an exact per-staged-record bool list and only then updates sent/abandoned/deadline counters; no second drain until debt settled, Stop forcibly abandons any debt. GameAdapter stages a maximum of8 already-due records, each lane maintains exactly one AEAD/PN and original record ID; `finish_staged` credits parity ID only for an actual proven kernel-copied record. A Game source first does not wait to fill a group.

Worker groups staged frozen handles by authenticated physical lane+original per-lane Go tuple. **>=2 same-lane due records** issue a single *real* `send_kernel_multimsg` (no re-encryption or second identity); **one ready record** uses immediate existing `send_one`. Only positive `accepted_prefix` from the actual Linux kernel is accepted, EAGAIN/preflight/short/partial/uncertain suffix dropped under existing bounded policy, consumed PN never reassigned, per-lane TCP seq advances only over proven prefix. Buffers and native FFI iovecs live across synchronous syscall under existing BorrowFence; Stop/owner finalization occurs after joins. Fixed6 parity plan/copy are separate from disabled outer DATA retry. No new per-packet thread, global socket, timer, long queue or old Go DATA passthrough.
