## Real interface and old path

`crates/wbd-platform/src/linux_raw_carrier.rs` already exposes `ScopedRawIpv4Rx::receive_kernel_multimsg` using real `linux_rx_batch::receive_fd` / Linux **recvmmsg(MSG_DONTWAIT|MSG_TRUNC)**, not four `recvfrom` calls. It checks original authenticated exact tuple via the existing kernel socket BPF and `parse_data_packet` on each returned slot and compacts **unauthenticated** ciphertext in-place. A synchronous BorrowFence spans the native syscall and strict parser; stop waits for actual completion before slabs/sockets release. `RawReadyBatch.observed` is actual kernel-completed slots; `Unauthenticated/Rejected/Truncated` are explicitly distinguished. Raw rejected/replayed bytes must never become a valid receive.

Previously, Game M4 lane worker in `crates/wbd-engine/src/v4_game_public_kernel.rs` used `recv_one_into` with a separate `poll`, `recvfrom`, strict parsing and 2048B scratch, **once per packet**, for both Game OFF and Game fixed6. CPU/host-pressure improvement cannot be presumed from interface availability. The only P1a product code changes are this worker, aggregated Stop counters, and no new keys/replay state.

## P1a code and hard boundaries

- One per-lane RX worker maintains exactly **four** independent `[u8;2048]` stack buffers and passes `&mut [&mut [u8];4]` to actual `receive_kernel_multimsg`. There is no socket or TUN scope change, no extra encryption, no heap Vec/channel/threadpool for batch slots. `recvmmsg` immediately returns currently available prefix without waiting to fill the batch. A single empty nonblocking receive parks in `poll(readiness_fd,20ms)`, which wakes immediately on new DATA; bounded Stop wake-up and no busy-spin on unexpected errors.
- For each observed slot, only `Unauthenticated{cipher_len>0}` advances to the **unchanged** per-lane AEAD+replay `GameReceiveOwner::prepare_receive/prepare_fec_batch`. `Rejected`, `Truncated`, `Unused` do not authenticate or deliver; stop/generation checked again per slot. FEC recovery remains ONE shared state. TUN writes stay **outside owner mutex**; preexisting `finish_fec_batch` multi-frame partial-write/Stop fail-closed contract and `finish_receive` write-success commit preserved. Source-first delivery is not delayed for batch filling. Each lane processes max 4 packets before checking another kernel turn; no endlessly held RX owner lock.
- Stop logs one aggregated `M0_GAME_M4_RX_MULTIMSG socket_calls/observed_records/full_4_batches/rejected_untrusted/valid_records/limit_per_syscall=4` line; no plaintext, secrets, per-packet log or diagnostic sampling in hot path. Network harness `require_game_rx_multimsg` is only legal on Game2/4; new bundle must demonstrate actual calls/valid records and coherent counts, while old bundle remains `NOT_OBSERVED`. This metric counts native syscall **attempts** and accepted kernel slots, not packets authenticated by AEAD, peer-ACKed, or successfully written to TUN.
- All previously validated 0/4/20/60ms Game4 due times, Game2 immediate send, Game fixed6 parity, first TUN delivery, generation, MTU, unique per-lane crypto/PN, outer DATA retransmit OFF remain unchanged. No bulk reuse of another lane's sealed ciphertext.
