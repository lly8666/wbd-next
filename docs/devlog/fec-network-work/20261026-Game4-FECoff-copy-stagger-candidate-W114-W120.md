## Design and bounds

Absolute T0 offsets: physical lane1=0, lane2=4ms, lane3=20ms, lane4=60ms. The first copy is never paced. Other input packets progress while later copies wait; lane FIFO heads only (4) are inspected to locate next due, no per-packet thread/timer, no all-queue scan. Rust's native TUN TX worker poll watches TUN readiness and earliest due with <=10ms Stop wake check. Encryption, per-lane PN/seq and actual kernel copy happen at real due dispatch. Queued `Pending` holds logical slot/lane/due/position only, each `Job` owns a single immutable reused source buffer. 5ms `max_age_ns` is measured **after individual due**, not from T0; stop/generation frees old owner queue. Native scheduled/sent/abandoned/average+maximum due-lateness are actual per position, both endpoints logged once on Stop, never counterfeited from product arguments.

Original 128 work slots cannot accommodate stagger. Upper bound for 3Mbps with only 64-byte application payload: `3e6/8/64 =5859.375` jobs/sec × `(0.060 + 0.005)s` ≈ **381 jobs**. New Game4 opt-in caps 1024 logical jobs, 1024 slots per lane, logical byte budget 2MiB, reused fixed-size 1024×2048B native arena (current Arena eagerly preallocates bounded slabs), Game RX logical dedup marker window 65536 bits=8KiB. Typical 3Mbps retained payload ~22.5KB per direction plus existing representation/metadata. For 100Mbps all-64B `195312.5pps×0.065=12695` jobs >1024, so high-PPS throughput is **NOT QUALIFIED/NO ESCALATION**. Receive window is not inflated by the common 75ms path delay.

CLI `--game4-copy-schedule=immediate|stagger-4-20-60`, default immediate, only `--mode=game4 --game-fec=off`; applies on each endpoint after protected Go TLS group committed, native group before M4 start. `outer-repair=off` independently true real data replay suppression. Config/harness per bundle `game4_copy_schedule` permits identical binary/same-VM sequential AB, not different builds. UI/Windows/Go Game2/Normal/old Game+FEC not wired.
